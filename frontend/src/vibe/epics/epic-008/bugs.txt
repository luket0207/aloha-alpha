## Bug-001 — Home Hero Logo Style Setting Missing

**Status:** complete

### Issue

In Epic-008 Feature-004, we added a requirement to switch the homepage Hero between two logo styles:

- Writing Logo — the existing text-based Aloha Academy logo.
- Round Logo — the `logo.png` image from the WordPress Media Library.

However, I cannot find this setting anywhere in the Home Hero block's Gutenberg editor.

I want this corrected so that I can easily switch between the two logos from the Home Hero block settings.

### 1. Investigate the Missing Setting

Before implementing a fix, inspect the existing Home Hero block registration and Gutenberg editor implementation.

Determine whether:

1. The Logo Style attribute was registered.
2. The Logo Style control was added to the editor.
3. The control is actually rendered in the correct Inspector Controls panel.
4. The updated Gutenberg JavaScript was built and enqueued correctly.
5. The editor might still be loading an older build.
6. The React frontend supports both logo styles.
7. The WordPress-to-React data contract exposes the selected style.

Identify the cause of the missing setting rather than creating duplicate functionality.

### 2. Add or Correct the Logo Style Selector

When selecting the **Home Hero** block in Gutenberg, I want a setting called:

**Logo Style**

Options:

- Writing Logo
- Round Logo

Requirements:

1. Display the selector in the Gutenberg Block settings sidebar.
2. Place it in an appropriate settings panel, preferably an Advanced or Logo Settings panel.
3. Make the setting available whenever the parent Home Hero block is selected.
4. Do not require selecting a nested image, logo or text block.
5. Default to Writing Logo.
6. Update the Gutenberg preview when changed.
7. Persist the selected value when saving the page.
8. Restore the correct value when reopening the editor.

The setting must be easy for a non-technical WordPress user to locate.

Do not place it exclusively in a hidden toolbar or an unrelated editor control.

### 3. WordPress Block Attribute

Ensure the block has a persistent attribute such as:

```js
logoStyle: {
  type: "string",
  default: "writing"
}
```

Only allow:

- `writing`
- `round`

Requirements:

- Existing Home Hero blocks without this attribute must default to Writing Logo.
- Updating the attribute must not cause Gutenberg block validation errors.
- The setting must not reset the slogan or carousel images.
- Changing logo styles must not recreate the Home Hero block.
- The setting must survive saving and reopening the page.

Use the existing block registration and persistence system.

### 4. Frontend Logo Switching

Ensure that the selected setting actually changes the public-facing Hero.

**Writing Logo**

- Display the existing Large Logo.
- Preserve its appearance, layout and positioning.
- Preserve the existing slogan arrangement.

**Round Logo**

- Display the WordPress-managed `logo.png`.
- Desktop target size: 250px × 250px.
- Scale responsively on smaller screens.
- Preserve image proportions.
- Centre the logo horizontally.
- Centre the existing slogan beneath it.
- Maintain 1rem of spacing between the Round Logo and slogan.

Do not hardcode the WordPress upload URL in React.

Use the existing stable image reference where available.

If the image cannot be resolved, report the problem and provide the minimum required WordPress image-selection step.

**The Logo Style selector must still be visible even if the Round Logo image is not yet configured.**

### 5. Preserve Existing Home Hero Functionality

Do not modify:

- Background carousel images.
- Carousel fade transitions.
- Slogan text or editing functionality.
- Water background animations.
- Hero waves.
- Full-viewport layout.
- Scroll-down button.
- Existing colours and typography.
- Other Gutenberg blocks or patterns.

The only visual difference should be the selected logo and its associated layout.

### 6. Verify the Actual Gutenberg Editor

Do not consider this bug resolved solely because the attribute or control exists in the source code.

Where the local WordPress environment is available:

1. Rebuild the relevant Gutenberg editor assets.
2. Open the WordPress Home page.
3. Select the parent Home Hero block.
4. Open the Block settings sidebar.
5. Confirm the Logo Style selector is visible.
6. Select Round Logo.
7. Confirm the preview updates.
8. Save and reopen the page.
9. Confirm Round Logo remains selected.
10. Verify the public React frontend displays the Round Logo.
11. Switch back to Writing Logo and verify the same process.

If actual editor verification is unavailable, report that limitation and provide precise manual verification instructions.

### Acceptance Criteria

- Logo Style appears in the Home Hero block settings.
- The selector is accessible from the parent block.
- Writing Logo and Round Logo options are available.
- Writing Logo is the default.
- Existing Home Hero blocks remain compatible.
- Changing the setting updates the editor preview.
- Changing the setting updates the public frontend.
- The selected value persists after saving.
- Round Logo uses the intended `logo.png` image.
- Round Logo uses the correct dimensions and slogan alignment.
- Switching does not modify the slogan or carousel images.

**Notes:** Complete. The selector, attribute, editor preview and frontend contract already existed; the missing-control cause was stale editor JavaScript because WordPress continued serving the changed source as `index.js?ver=0.2.0`. Updated the existing editor asset manifest from the static plugin version to a source-file cache version while retaining its explicit WordPress package dependencies, so the URL now changes when the directly authored editor script changes. Also protected the required 1rem Round Logo slogan gap from the short-mobile Hero override discovered during live verification. The actual Home page was tested in Gutenberg: the parent block exposed Logo Style, Round saved/reopened with the real `logo.png`, the public Hero rendered it at 250×250px with a 16px gap, then Writing saved/reopened and was restored publicly. The slogan, six carousel image IDs, six public slides and eight water animations remained unchanged. PHP/JS syntax, four focused Hero tests and the production build passed.

**Left**

Requirements:
