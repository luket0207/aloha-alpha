`AlohaButton`

- Green Group.
- Light Blue Group.
- Cream Group.
- Grey Group.

## 2. Add Scroll-Triggered Link Animations

### Final State

## 3. Animation Duration

Each individual link should take:

**0.5 seconds (500ms)**

Use smooth easing appropriate for an object falling gently into position.

The movement should feel natural rather than abrupt or excessively bouncy.

Do not introduce unnecessary overshoot.

## 4. Staggered Animation Timing

Animate links one at a time, overlapping their animation periods.

Each successive link should begin **0.25 seconds (250ms)** after the previous link begins.

### Example: Eight Links

| Link | Start | Finish |
|---|---|---|
| Link 1 | 0.00s | 0.50s |
| Link 2 | 0.25s | 0.75s |
| Link 3 | 0.50s | 1.00s |
| Link 4 | 0.75s | 1.25s |
| Link 5 | 1.00s | 1.50s |
| Link 6 | 1.25s | 1.75s |
| Link 7 | 1.50s | 2.00s |
| Link 8 | 1.75s | 2.25s |

### Implementation

Use the link's index to determine its delay.

Suggested calculation:

```js
const animationDelay = index * 0.25;
```

And apply a duration of:

```scss
animation-duration: 0.5s;
```

Requirements:

1. Start with the first link.
2. Animate links in their existing WordPress order.
3. Start each subsequent animation 250ms later.
4. Allow animations to overlap.
5. Do not wait for a previous animation to finish completely.
6. Continue the sequence across multiple rows.
7. Preserve the same stagger timing on desktop, tablet and mobile.
8. Support any number of links dynamically.

Do not hardcode the animation for a specific number of links.

## 5. Scroll Direction Behaviour

The entrance animation should behave like the other direction-sensitive scroll animations already implemented on the website.

### Scrolling Downwards

When the Page Links section enters the viewport while scrolling down:

1. Trigger the entrance sequence.
2. Start animating the first link.
3. Stagger the remaining links by 250ms each.
4. Continue until every link has reached its resting position.

Trigger the sequence when the links are sufficiently visible, rather than waiting until the entire section has entered the viewport.

### Scrolling Upwards

When scrolling upwards into the Page Links section:

- Do not trigger the entrance animation.
- Do not fade the links out.
- Do not move the links back to their starting positions.
- Display them normally in their completed state.

### Resetting

Allow the entrance animation to replay on a future downward entry.

Requirements:

1. Track whether the section is visible.
2. Track the direction of scrolling.
3. Reset the animation when the section has completely left the viewport and a subsequent downward entry can be prepared.
4. Never visibly reset links while they remain in the viewport.
5. Do not replay the animation merely because the user scrolls upward.
6. Avoid animation flickering near viewport boundaries.
7. Prevent unnecessary state updates during scrolling.

When the user passes completely above the section and later scrolls down to it again, the staggered animation should be able to replay.

When re-entering from below while scrolling upwards, the links should appear immediately without an entrance animation.

Reuse the website's existing IntersectionObserver and scroll-direction utilities where possible.
